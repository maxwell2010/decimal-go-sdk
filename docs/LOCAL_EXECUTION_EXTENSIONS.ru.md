# Расширенные проверки локального исполнения

[English](LOCAL_EXECUTION_EXTENSIONS.md) | [Предыдущие локальные фикстуры](LOCAL_EVM_TESTS.ru.md) | [Валидация](VALIDATION.md)

Наборы добавляют исполняемые доказательства с разными границами. Они не подтверждают публичные deployment, консенсус Decimal или settlement. Обычные прогоны не требуют публичного RPC, пользовательского кошелька или средств. Снимок Safe получен только чтением; все описанные ниже транзакции исполняются локально.

```sh
go test -run '^(TestLocalEVM|TestLocalChain)' .
```

## Выбранный runtime Checks на 6318 байт принимает профиль подписи SDK

[Манифест актуального снимка Checks](../testdata/evm/checks-current-manifest.json) фиксирует код, прочитанный из официальной testnet-реализации `0xBACA5A733002F5323aBE4c83C91B87212E7A3ca3`: chain 202020, блок 22477428, исходный RPC hash `0xfb67691493eda26389cac1a122c8a6396192d97b153857d5ed3c87a10cf22d0c`. Runtime содержит 6318 байт, keccak256 `0x78da094992fb84bf17517277dcfc9c67ab36ba535f8879b5fd5b5614ac397bf4`. До установки кода в пустое локальное состояние проверяются SHA-256 снимка и эти идентификаторы.

`TestLocalEVMObservedCurrentChecksRuntimeSigning` создаёт обеспеченный локальный чек на выбранном коде, получает настоящий возвращённый и опубликованный в событии хеш, затем использует публичный помощник SDK `SignEVMCheckRedemption`. Неверный caller отклоняется без изменений; назначенный получатель погашает 100 raw DEL с ожидаемыми событием и балансами. Трасса ECRECOVER соответствует digest SDK для каждого caller. Повторное погашение отклоняется без сохранённых эффектов.

Это положительно подтверждает привязанный к получателю профиль подписи SDK в проверенных путях именно этого кода. Неопределённость профиля для выбранного снимка закрыта; несовместимый исторический артефакт на 6258 байт сохраняется отдельной регрессией. Доказательством служат точная идентичность кода, трасса digest и успешное исполнение, а не один размер runtime. Тест не копирует живое storage, не подтверждает инициализацию или владельцев публичного proxy, все маршруты Checks и публичный приём транзакции/settlement. Начальные nonce и балансы относятся к новой локальной фикстуре.

## Weighted Safe и фабрика

[Манифест Safe](../testdata/evm/safe-manifest.json) закрепляет runtime, полученный из официального testnet RPC: chain 202020, блок 22477428, исходный RPC hash `0xfb67691493eda26389cac1a122c8a6396192d97b153857d5ed3c87a10cf22d0c`. Перед исполнением проверяются SHA-256 снимка и отдельные keccak256 кода реализации и фабрики. Это runtime-only артефакт, не верифицированный Solidity-исходник и не оригинальный creation bytecode.

Код устанавливается в локальный StateDB без копирования живого storage. Настоящая фабрика создаёт и инициализирует новый proxy с синтетическими владельцами весов 2 и 1, порогом 3. Тесты сравнивают хеш Safe-транзакции SDK с getter контракта, отклоняют недостаточный вес подписей, исполняют подписанный перевод и запрещают replay. Результат относится к выбранному коду и новому локальному proxy, не к владельцам, инициализации или полномочиям публичного Safe. Обычный Gnosis-контракт не подменяет weighted Safe Decimal.

## Стандартный EIP2612 permit

[Манифест permit](../testdata/evm/permit-manifest.json) закрепляет официальный OpenZeppelin Contracts v4.7.2, commit `64e48203cecad94f02de9891ecdeed4d629c6dae`, полные compiler inputs и хеши артефактов. Upstream ERC20PermitMock явно служит СТАНДАРТНОЙ фикстурой совместимости, а не токеном Decimal. Для пересборки используются включённые исходники и закреплённый компилятор; обычные тесты исполняют готовый bytecode.

Тесты используют CheckedPermit и typed-data helpers SDK, проверяют изменение allowance и nonce, отклоняют replay, неверные name/chain/contract домена, nonce и истёкший срок, затем расходуют allowance через transferFrom. Это проверка стандартных путей подписи. Она не переводит permit-профили Decimal в статус подтверждённого deployment.

## Взаимодействие исторического токена и Checks

Существующие официальные исторические артефакты NewToken и Checks исполняются совместно. Проверяются approve, custody токенов, возвращённые хеши чеков, события создания/погашения и расход allowance. Отсутствующий или частичный allowance и недостаточный баланс откатываются без логов, изменения custody и nonce вызывающего адреса.

Batch из двух чеков с верной первой и неверной второй подписью должен откатываться целиком. Следующий корректный batch погашает оба чека, подтверждая откат статусов и переводов; replay отклоняется. Подписи используют наблюдаемый check-only digest исторического артефакта только внутри тестов. Несовпадение с JS-помощником, привязанным к получателю, сохраняется явно.

## Подписанные транзакции локальной Ethereum-сети

Симулированная Ethereum-сеть в памяти использует chain ID 1337 и синтетические ключи. SDK Send/Broadcast/WaitReceipt проверяют legacy type 0, access-list type 1 и dynamic-fee type 2: committed block/receipt, подписанный intent, сумму получателя, уменьшение баланса отправителя на value плюс фактическую комиссию и расход nonce. Зафиксированный REVERT списывает gas и расходует nonce, откатывая value и логи; неудачная оценка gas nonce не расходует.

Этот набор действительно подписывает и майнит локальные тестовые транзакции. В публичную сеть они не отправляются. Discovery, внешние подключения и публичные RPC URL выключены; тесты используют in-process RPC, обычные HTTP/WS/IPC listeners выключены, а необходимый backend authenticated service ограничен ephemeral loopback. Локальная Ethereum-сеть не воспроизводит консенсус Decimal, native-модули, публичные комиссии или состояние deployment.
