# October 2026 Delegation response compatibility

[Russian guide with a read example](DELEGATION_UPGRADE.ru.md). [Official source manifest](DELEGATION_UPGRADE_SOURCES.json).

The official node binding at commit `a46cb48d7965c1a64a495cebb22e735dfe4b9da3` appends `uint256 holdStartTime` to the seven-field `Stake` tuple. `amount` remains at index 3, `holdTimestamp` at index 6 and the new hold start at index 7. Values remain raw integers. No amount scaling is introduced.

The built-in `Delegation` readers accept both canonical layouts for `getStake`, `getStakes`, `getHoldStake`, `getHoldStakeDEL`, `getFrozenStake` and `getFrozenStakes`, including nested frozen tuples and arrays. Generated results expose `HoldStartTime *big.Int`: nil means the legacy response omitted the field, while a nonnil zero means the current response explicitly returned zero. Invalid offsets, counts, lengths, padding and trailing bytes return errors. A failed read is never substituted with a zero stake. Selectors remain unchanged. Existing `Contract.ReadAt` supports reads at a chosen block.

`Delegation.DecodeLog` accepts original legacy and current event signatures. It preserves their actual topic, tuple fields and original log, with strict data/topic validation. A legacy event retains seven fields. Node hook normalization does not rewrite the original transaction receipt. Newly added official unified NFT events are decoded without changing transaction routes or approvals.

The official `DelegationNFT` binding at the same commit still has seven-field stakes. Its ABI and existing read/exit builders remain available. New delegate/hold/permit calls through the built-in profile are rejected offline for chain 75 at the known retired address `0xe45adfcc739a0d10ce9462b58866c9a1a06035e2`. Other addresses, networks and explicitly supplied ABIs are not rerouted. Legacy positions retain their correct contract route. No automatic migration or NFT owner lookup is added; ERC721 `ownerOf` must not be applied indiscriminately to ERC1155.

Use `client.UnifiedNFTDelegation(unifiedProxy)` explicitly for new positions. Go has no implicit NFT service route in global Config. The constructor makes no network call and changes no configuration. Its separate `NFTStake` has exactly ten official fields. `ReadNFTStakeAt` and `ReadNFTStakeIDAt` require a block number. Thirteen official delegate/hold/transfer/withdraw builders include the available ERC721 permit route; missing ERC1155 permit variants are not invented. `BuildERC721Approval` creates token-specific approval calldata, while `BuildERC1155ApprovalForAll` explicitly creates a collection-wide grant. Both derive their operator from the selected unified destination. These builders do not submit approvals, sign or send transactions.

`Contract.DecodeDelegationReceipt` filters by contract address, preserves original ordering and retains repeated stake IDs with distinct exit indexes. Unknown events are skipped; malformed known events fail without a partial result. Original receipts remain unchanged. Old and current node event layouts were also compared with the official `delegationv7` binding; all sixteen pinned legacy event definitions match after excluding descriptive internalType metadata.

Pinned `abi/` artifacts and `ABIJSON("Delegation")` retain their original provenance. The additional exact official ABI is embedded from `delegation_compat/`. Compatibility dispatch only applies to the built-in Delegation profile; `ContractWithABI` continues to use its explicitly supplied schema. The SDK has no validator valuation aggregator or stake-value cache. Applications remain responsible for data completeness, freshness, validator state and cache invalidation across network upgrades.

Offline synthetic responses and logs exercise decoding and amount preservation. Additional saved mainnet RPC fixtures supplied by a coordinating project contain eight eight-field stakes at block `0x20c2060`, 16 original `StakeUpdated`/`StakeAmountUpdated` logs and two empty-position NFT view probes. Their exact copied bytes and SHA256 are recorded; these reads were not independently repeated here. Tests compare event/getter amounts and raw ABI words. This establishes compatibility with those samples, not a funded NFT lifecycle or general deployment acceptance. No public transactions, history reprocessing or production deployment are performed for this change.
