# Дополнительные локальные маршруты контрактов

[English](LOCAL_CONTRACT_ROUTES.md) | [Основа исполнения](LOCAL_EXECUTION_EXTENSIONS.ru.md) | [Валидация](VALIDATION.md)

Сценарии исполняют настоящий код из проверенных фикстур с синтетическими локальными аккаунтами и балансами. Обычные тесты не обращаются к публичному RPC и не отправляют публичные транзакции. Свежие локальные состояния не подтверждают инициализацию сетевых proxy, права пользователя, консенсус Decimal или settlement.

```sh
go test -run '^(TestLocalEVMCurrentChecks|TestLocalEVMWeightedSafeOwner|TestLocalEVMObservedDecimalReserveless)' .
```

## Маршруты наблюдавшегося Checks

[Фикстура Checks](../testdata/evm/checks-current-manifest.json) закрепляет наблюдавшуюся реализацию на 6318 байт. Новые тесты используют подпись SDK с привязкой к получателю, а не подпись только хеша из исторического артефакта.

Создание токеновых чеков требует настоящих allowance и обеспечения. Отсутствие или недостаток allowance и недостаточный баланс отклоняются без изменений custody, allowance, nonce и логов. Batch с корректным первым погашением и неверной второй подписью откатывает все переводы и статусы; следующий корректный batch проходит, replay отклоняется. Просроченные подписи получателя также отклоняются.

`createChecksTokenByPermit` отдельно исполняется со стандартной официальной EIP2612-фикстурой upstream. Корректное создание проходит реальные permit и custody; просроченное разрешение или неверная сумма откатывают изменения. Этот тест взаимодействия не выдаёт upstream-токен за Decimal deployment.

## Администрирование weighted Safe

[Фикстура Safe](../testdata/evm/safe-manifest.json) сначала создаёт настоящий proxy через factory. Прямой вызов владельца не может изменить threshold. Подписанные self-call меняют threshold, добавляют владельца с весом и удаляют владельца по фактически возвращённому порядку списка. Подписи другой chain ID, посторонних и удалённых владельцев не дают полномочий.

Невозможный threshold откатывает владельцев, порог, nonce и логи; следующая корректная операция проходит. Действующий владелец может подтвердить хеш транзакции без расходования execution nonce; удалённый владелец этого сделать не может. Проверяется наблюдавшийся weighted runtime и локальная настройка, а не владение публичным Safe или все маршруты contract signatures/modules.

## Permit наблюдавшегося Decimal reserveless token

[Манифест token runtime](../testdata/evm/token-runtime-manifest.json) содержит официальные снимки reserve и reserveless реализаций на фиксированном блоке. Reserveless-фикстура инициализируется через настоящий публичный ABI в пустом локальном состоянии. SDK CheckedPermit проверяет реальные domain и nonce; permit создаёт Approval и меняет allowance/nonce, replay отклоняется, transferFrom расходует allowance. Повторная инициализация отклоняется.

Так закрывается прежнее ограничение permit-тестов только upstream-фикстурой для конкретного наблюдавшегося Decimal reserveless кода. Это всё ещё не подтверждает состояние публичного proxy или все маршруты токена. Код reserve-токена прочитан и проверен по хешу, но НЕ исполняется этим набором; экономика резервов и приёмка из него не выводятся.

Отдельный [набор проверок экономики reserve-токена](RESERVE_ECONOMY.ru.md) теперь исполняет закреплённый reserve-runtime: выбранные нелинейные обмены, учёт балансов, возврат сдачи, burn, границы и dust. Утверждение о чтении без исполнения выше относится к permit-набору, а не к этим дополнительным проверкам.
