# Pinned stateless Cosmos validation

`cosmos.ValidateBasic` ports the stateless acceptance predicates for all 43 request schemas from node commit `9e6c6d7`, and the two upgrade message policies from Cosmos SDK v0.46.16. It accepts the embedded schema-backed message constructors. Other message types return `ErrUnsupportedValidation`; foreign or altered descriptors are rejected by identity against the embedded schema, even when they reuse the same FullName and signer field name. GetSigners enforces the same schema boundary. Decode foreign wire bytes into the pinned constructor before applying these APIs. Validation never changes the input or contacts a node.

`cosmos/schema/validation-sources.json` records every request's source file, line, permalink and SHA-256, plus configuration/helper dependencies. Regenerate using `python tools/validation_sources.py --node PATH --sdk PATH`. A dirty node source tree is rejected for these policy inputs. Runtime validation does not read those source trees.

Implemented predicates include the correct account/operator HRPs, Decimal versus SDK coin denomination rules, positive amounts, CRR/supply/reserve/emission bounds, collection identifiers and quantities, NFT sub-ID uniqueness, validator descriptions/pubkey presence/commission, creation heights, multisig owner/weight/threshold rules, swap chain/transaction/signature shapes, oracle price uniqueness and upgrade-plan constraints. Custom integer strings inspected by a predicate fail closed when malformed rather than reproducing nil-integer panics of hand-constructed upstream values. SDK decimals use the pinned 315-bit scaled-integer wire representation, not a guessed floating-point representation.

These are compatibility predicates, not authorization or a stronger application security policy. In particular, source behavior is intentionally retained:

- RedeemCheck checks only its sender in upstream ValidateBasic; actual check/proof validation is separate. Use the historical check helpers for their explicit checks.
- NFT UpdateReserve rejects zero, but its ValidateBasic predicate does not reject a negative nonzero reserve.
- Multisig threshold zero is not rejected if the source's weight-sum comparison passes.
- CancelRedelegation does not use the ordinary Redelegate self-destination rejection.
- Collection IDs are trimmed only where the source trims them; comparison semantics are not silently changed.

The pinned application overrides SDK coin denomination validation with 231 historical exceptions in `app/denom_whitelist.go`. Its interaction with SDK46 `SetCoinDenomRegex` preserves an ungrouped alternation expression. Consequently its match behavior is broader than a strict whole-string denomination policy. The port reproduces the source expression and records the exact exception list in `validation-denom-whitelist.json`. Applications requiring stricter denominations should add an explicit policy; this compatibility validator is not advertised as a security filter.

All 43 schemas have valid, empty and invalid-signer fixtures, with additional boundary tests for amounts, supply, CRR, quantities, duplicate IDs/prices, self transfer/redelegation, signature shapes and commissions. An actually executed SDK46 reference (`cosmos/tools/reference/validation`) produces eleven upgrade validation vectors in `cosmos/schema/validation-reference.json`; our validator matches their accept/reject decisions. A second isolated reference (`cosmos/tools/node-validation-reference`) actually executes all 43 official ValidateBasic implementations, including all 41 Decimal node requests. Its 129 public wire cases (valid, empty and bad signer for every type) produced zero mismatches, panics or decode errors, recorded in `validation-node-reference.json`. The regression suite compares local decisions against this output. Dependency checksums were verified in an isolated cache before execution; exact module versions, checksums and fixture hashes are in `validation-node-reference-provenance.json`. These finite differential fixtures are evidence for their inputs, not proof over every possible message.

Role membership, oracle authority, balances, validator state, stateful caps, chain parameters, current ante admission and successful transaction execution remain node responsibilities. The eight-type native ante allowlist is independent of ValidateBasic success. No network transaction is sent by validation or these tests.
