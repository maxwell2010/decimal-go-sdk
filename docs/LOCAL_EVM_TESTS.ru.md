# Локальное исполнение EVM и устойчивость RPC

[English](LOCAL_EVM_TESTS.md) | [Проверки](VALIDATION.md) | [Совместимость](COMPATIBILITY.ru.md)

## Область проверки

Локальный набор исполняет настоящие creation/runtime bytecode контрактов во встроенной EVM go-ethereum с локальной базой состояния. Исполнение контрактов не заменяется mock Backend. Не нужны процесс ноды, публичный RPC, файлы кошелька или пополненный счёт. Используются адреса и балансы тестовых фикстур. Этот набор не подписывает, не майнит и не отправляет блокчейн-транзакции.

Запуск из корня исходников SDK:

```sh
go test -run '^TestLocalEVM' .
```

Используются доступные исторические фикстуры токена и Checks. Проверки предназначены для контроля состояния, событий и ожидаемых отказов, а не только успешного ABI-кодирования. Результаты конкретного релиза записываются в [VALIDATION.md](VALIDATION.md); эта страница описывает область проверки и воспроизведение, но отдельно не утверждает успешность всех сценариев.

## Несовпадение подписи Checks, обнаруженное исполнением

**Закреплённый профиль подписи JS-исходника и bytecode Checks из комплекта не взаимозаменяемы.** Runtime артефакта содержит 6258 байт. При локальном исполнении трасса ECRECOVER получает `accounts.TextHash(checkHash[:])`, без зависимости от caller погашения в проверенных путях. Помощник SDK следует проверенному официальному JS-исходнику: он связывает hash чека и redeemer, затем применяет personal-sign prefix. Bytecode этого артефакта отклоняет такую подпись с `InvalidSignature` для обоих проверенных callers; отклонённые вызовы сохраняют балансы. Несовпадение явно зафиксировано в `TestLocalEVMOfficialChecksCreationAndSigningProfileMismatch` и не выдаётся за успешное покрытие погашения.

Помощник подписи SDK не меняется. Отдельный положительный путь исторической фикстуры использует синтетическую подпись непосредственно наблюдаемого digest только внутри тестов. Это не новый публичный API подписи и не рекомендация для публичных deployment. Привязка к получателю для исторического артефакта не обещается. У наблюдённой публичной реализации Checks runtime содержит 6318 байт - это другой артефакт. Размер и локальный результат не устанавливают поколение подписи развёрнутого контракта или совместимость реального погашения. Для каждого deployment нужна отдельная проверка.

## Подлинные официальные фикстуры

[Манифест фикстур](../testdata/evm/manifest.json) содержит закреплённые источники и SHA-256. Исходники и артефакты включены в репозиторий. Обычные Go-тесты не запускают Solidity-компилятор и не требуют дополнительных загрузок помимо Go-зависимостей.

- Исторический `NewToken`: точный `decimalToken.sol` из официального `decimalteam/decimal-contracts`, commit `018a6c6d00616c3e24ae44a8fac429b2ccabbd12`. Компилятор solc `0.8.17+commit.8df45f5f.Emscripten.clang`, оптимизатор выключен, целевая EVM London. Доступны transfer, approve, transferFrom, mint с правами владельца, burn и burnFrom. Конструктор создаёт начальную эмиссию с множителем 10^18. Этот исторический контракт не подтверждает эквивалентность текущим развёрнутым токенам Decimal; метода permit в нём нет.
- Checks: неизменённый артефакт ABI/creation/runtime из официального `dsc-js-sdk`, commit `6790d35e2decb0cbb06a9149a9c476c834f99223`, файл `src/decimalevm/abi/Checks.json`. Исполнение фикстуры реализации не подтверждает инициализацию proxy, адрес deployment в сети, обеспечение чека или приём погашения в production.

[Описание compiler package](../testdata/evm/compiler-package.json), [lockfile](../testdata/evm/compiler-package-lock.json) и [инструмент пересборки](../tools/rebuild_local_evm_fixture.py) позволяют сопровождающему явно воспроизвести результат с точным пакетом solc. Перед запуском прочитайте usage инструмента; ему нужен путь к локальному компилятору. Обычные тесты используют проверенный bytecode из репозитория. Лицензионные уведомления исходников сохраняются.

Дополнительные локальные тесты исполняют настоящий официальный runtime weighted Safe/factory и стандартную EIP2612-фикстуру OpenZeppelin. Также проверяются исторические токеновые Checks и отдельная изолированная Ethereum-цепочка с подписанными транзакциями. См. [расширение проверок](LOCAL_EXECUTION_EXTENSIONS.ru.md). Эти результаты не подтверждают владение публичным Safe или приём permit в Decimal deployment. Отсутствующая официальная исполнимая фикстура остаётся непроверенным случаем. Самописный контракт не выдаётся за доказательство deployment. Набор также не доказывает совместимость консенсуса Decimal, учёт сетевых комиссий, майнинг через RPC, инициализацию proxy, межсетевой settlement или исполнение всех ABI-профилей SDK.

## Отказы HTTP JSON-RPC

```sh
go test -run '^TestRPCResilience' .
```

Тесты используют настоящий HTTP transport SDK и локальные серверы `httptest`. Проверяются HTTP 429/503, разрыв соединения, повреждённый JSON, JSON-RPC errors, истечение deadline ожидающего запроса и несогласованные поля receipt. Контролируются отсутствие утечек деталей ответа и число запросов, включая отсутствие автоматической повторной отправки после неопределённого результата broadcast. Подписанные байты транзакций здесь относятся к синтетическим фикстурам и передаются только локальному HTTP-серверу.

Тест локального транспорта, исполнение во встроенной EVM и приём публичной нодой - разные виды доказательств. Ограничения наблюдений за реорганизацией и состоянием описаны в [разборе RPC ноды](NODE_RPC_IDENTITY.md).

## Ограниченные fuzz-кампании декодеров

Каждая команда запускает отдельную ограниченную кампанию с двумя workers:

```sh
go test -run '^$' -fuzz '^FuzzChecksEventDecoding$' -fuzztime 7s -parallel 2 .
go test -run '^$' -fuzz '^FuzzChecksReceiptDecoding$' -fuzztime 7s -parallel 2 .
go test -run '^$' -fuzz '^FuzzChecksSignatureRecovery$' -fuzztime 7s -parallel 2 .
```

Начальные данные взяты из сохранённых официальных receipt/events Checks и независимо исполненных JS-векторов подписи. Проверяются детерминированность декодирования и восстановления подписи, неизменность входа, независимое владение выходными буферами и отдельная ECDSA-проверка. Длина входных данных ограничена. Первые кампании 2026-10-29 прошли: 214141 исполнение для событий, 327 для receipt и 65124 для подписей. Числа зависят от машины и корпуса fuzzing и не являются процентом покрытия или приёмки. В этих ограниченных запусках сбоев не найдено; они не доказывают отсутствие всех дефектов.

Отдельно прочитанный официальный runtime реализации на 6318 байт теперь исполнен напрямую: он принимает подпись SDK с привязкой к получателю, отклоняет другого caller и replay, а ECRECOVER получает digest помощника. Это разрешает профиль конкретного наблюдённого кода, но не превращает исторический артефакт в текущий и не доказывает инициализацию, обеспечение или settlement публичного proxy. См. [исполнение наблюдённого кода](LOCAL_EXECUTION_EXTENSIONS.ru.md).
